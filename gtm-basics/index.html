Growth ToolboxTriggers, tags and variablesJesper Åström

The title sits between script tags on purpose: Tag Manager is one script on the page, and everything else happens inside a web tool. Today: what it is for, the three building blocks, and then the same three exercises on three pages of the practice shop.

Intro

What is Google Tag Manager for?

One piece of code on the site. All your tracking managed in a web tool.

Without Tag Manager

  • Google Analytics wants its code on every page.
  • Meta, LinkedIn and Google Ads each want their own code.
  • Every change means asking a developer and waiting for a release.

With Tag Manager

  • The developer pastes one snippet, once.
  • You add and change tracking at tagmanager.google.com.
  • You test it in Preview mode and publish when it works. No release needed.
Ask the class: who has asked a developer to add a pixel and waited two weeks? That is the problem Tag Manager solves. It is a container: one script that loads all the other scripts, controlled from a web interface.

Intro

How the container works

Four things happen, in this order, on every page.

  1. The page loads. The snippet in the page loads your container.
  2. The container watches the page: page views, clicks, form submits, messages from the developer.
  3. When something happens, the container checks its triggers.
  4. If a trigger matches, its tag runs and sends data somewhere, for example to Google Analytics.
<!-- Google Tag Manager -->
<script>(function(w,d,s,l,i){ …
  j.src='https://www.googletagmanager.com/gtm.js?id='+i
})(window,document,'script','dataLayer','GTM-W2S6DPBK');
</script>

This is the snippet. The ID at the end is the container. You already pasted yours into the practice shop.

Point at the container ID. Everything the students build today lives inside that ID. The page never changes again; the container does.

Intro

Three building blocks

Everything you build in Tag Manager is one of these three.

Tag

What to do.

Send an event to Google Analytics. Load the Meta pixel. Run a piece of code.

Trigger

When to do it.

On every page view. When a button is clicked. When the developer says a form was sent.

Variable

With which information.

The text on the button. The URL of the page. The price of the product.

One sentence "Send an event to Google Analytics (tag) when someone clicks Subscribe (trigger) and include which plan they chose (variable)."
Write the sentence on the board and underline the three parts. Every exercise today is that sentence with different words.

Intro

What is a Tag?

A piece of code that sends data somewhere.

  • Tag Manager has ready-made tags for Google Analytics, Google Ads, Floodlight and many others. You fill in a form, no code.
  • Custom HTML is the tag type for anything else: paste the code a tool gives you.
  • A tag does nothing on its own. It waits for a trigger.
  • Today we use one type: Google Analytics: GA4 Event. It sends an event with a name and some parameters.

The tag we build today

Measurement IDG-XXXXXXXXXX

Event Parameterscta_location = {{dlv - cta.location}}

Show the table and say: this is the whole tag. Five fields. The double curly braces are how Tag Manager writes a variable. We get there in Part 3.

Intro

What is a Trigger?

The rule that decides when a tag fires.

  • A trigger has a type: Page View, Click, Form Submission, Custom Event, Scroll and more.
  • A trigger can fire on all events of that type, or on some, with a condition. "All clicks" or "clicks where Click Text equals Subscribe".
  • One trigger can be used by many tags. One tag can have many triggers.
  • The condition uses a variable. That is why the three blocks belong together.

The trigger types we use today

TypeFires when
Click - All ElementsAnything on the page is clicked.
Custom EventThe developer pushes an event with that name.

Page View you already used in the course "Tag Manager on a real site".

Two trigger types cover most real work: click triggers when you have to work with what is on the page, custom event triggers when the developer helps you. The whole of Part 1 is about choosing between them.

Intro

What are Variables?

Named values Tag Manager reads from the page.

Built-in variables

Come with Tag Manager. You switch them on.

  • Page URL, Page Path
  • Click Text, Click Classes, Click ID, Click URL, Click Element

User-defined variables

You create them and give them a name.

  • Data Layer Variable: reads a value the developer put in the dataLayer. Today's main tool.
  • Auto-Event Variable: reads something from the element that was clicked.
Used in two places In a trigger, as the condition. In a tag, as the information you send. Written as {{Click Text}}.
Built-in variables are free but only know about the page: text, classes, URL. Data Layer Variables know what the developer knows: product name, price, plan. Exercises go from built-in to data layer.

Intro

The dataLayer

A list on the page. The developer writes to it. Tag Manager reads from it.

window.dataLayer.push({
  event: 'cta_click',
  cta: {
    text: 'Start your subscription',
    location: 'hero',
    destination: 'signup.html'
  }
});

This is what the practice shop pushes when a call-to-action button is clicked. It is in site/site.js.

  • event is a special key. It is what a Custom Event trigger listens for.
  • cta is an object with three values inside it. That is a nested value.
  • You reach a nested value with dot notation: cta.location is hero.
  • Values pushed without an event key, like page.type, fire no trigger but can be read by every tag.
Read the push out loud: "event cta_click, and an object called cta with text, location and destination". Dot notation is the one syntax they must learn today. Everything in Part 3 is dot notation.

Intro

Preview mode

See what fires before you publish. You will live in this window today.

  1. In Tag Manager, click the Preview button at the top right.
  2. A tool called Tag Assistant opens. Paste the address of your site and click Connect.
  3. Your site opens in a new window with a small badge that says it is connected.
  4. Back in Tag Assistant: the left column lists everything that happened. The middle shows which tags fired for the selected event.

The three tabs in the middle

  • Tags: Tags Fired and Tags Not Fired for the selected event.
  • Variables: every variable and its value at that moment.
  • Data Layer: exactly what the developer pushed.
Preview mode does not change the live site; only your browser sees the unpublished container. Tag Assistant cannot connect to a file on disk, the site must be online.

Part 1 · Advice

Five ways to filter a click

Pick the one that is unique to the button and will not change next month.

ConditionFor the hero buttonGood and bad
Click Text equalsStart your subscriptionEasy to read. Breaks when the copywriter changes the text, or the site is translated.
Click Classes equalsbtnStable. But every button on the site has the class btn, so it matches all of them.
Click URL containssignup.htmlGood for links. Matches every link to the signup page, also the one in the footer.
Click ID equalsnothing, the button has no idBest when it exists. Ask the developer to add one if you need it.
Click Element matches CSS selector[data-cta="hero"]Precise, uses anything from Inspect. Needs a CSS selector, which you learned in the scraping lecture.
Combine conditions with the plus button: Click Classes equals btn AND Click URL contains signup.html gives exactly the hero button and the footer link. The CSS selector row is the bridge to the scraping deck: same selectors.

Part 1 · Advice

When there is no custom event

First look for one. Then choose.

How to look

  1. Open Preview mode and do the thing: click, submit, add to cart.
  2. Read the left column in Tag Assistant. A row with a name the developer chose, like cta_click, is a custom event.
  3. Only rows called Click, Form Submit, Scroll Depth? Then there is no custom event for it.

Then

  • Custom event exists: use a Custom Event trigger. Always.
  • No custom event: use a Click trigger with the most stable filter from the table. Works today, may break later.
  • You need data the page does not show, like a price or a user id: write a specification and ask the developer for a push. Exercise 6 in the shop course shows how.
The footer newsletter form on the shop pushes nothing. It is the example of "no custom event" and it is what exercise 6 in gtm-real-site is about.

Part 3 · Advice

Which variable when

Built-in for what the page looks like. Data Layer for what the page knows.

Built-in: Click Text, Click URL, Page Path

  • Zero setup, always available.
  • Knows only what is visible in the HTML.
  • Use in click triggers when there is no custom event.

Data Layer Variable: dlv - cta.location

  • One variable per path. Version 2, dot notation.
  • Knows what the developer knows: prices, plans, ids, consent.
  • Use in custom event triggers and as tag parameters.
Rule Name the variable after the path: dlv - cta.location for cta.location. Six months later you will thank yourself.

Same on the home page: the tag uses CE - cta_click - hero, so Click - hero button is no longer used by anything. Delete it or keep it as a reminder. Unused triggers do no harm.

Why delete?

  • Two tags on one click means every add to cart counts twice in Google Analytics.
  • A container full of old tags is hard to understand for the next person.
  • Nothing is lost: Tag Manager keeps versions, and you can restore a deleted item before you publish.

Summary

What you did today

Tag, trigger, variable. Three pages, same three moves.

  • A trigger decides when. A Click trigger with a filter when you must, a Custom Event trigger when the developer pushes one.
  • A tag decides what. One GA4 Event tag with a name you choose and parameters you attach.
  • A variable carries the information. Built-in for the page, Data Layer Variable with dot notation for what the developer knows.
  • Preview mode is where you check every step: left column, Tags, Variables, Data Layer.
