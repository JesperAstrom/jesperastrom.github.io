The title sits between a request and a response on purpose: that is the whole topic. You ask, the server answers. Today: what an API is, how to read an address and an answer, then a real account, a real key and a real dataset from Kaggle. Two hours: 25 minutes intro, then four parts of roughly 10, 20, 30 and 25 minutes.

Intro

What is an API?

A website for programs. You ask with an address. You get data back, not a page.

A website

  • You type an address. You get a page: text, images, buttons, layout.
  • Made for people to look at.
  • To reuse the numbers on it you copy them by hand, or scrape the page.

An API

  • A program types an address. It gets data: plain text in a fixed shape.
  • Made for other programs to read.
  • Same question, same shape of answer, every time. No layout to fight with.
In one sentence An API is the door a service opens so that other programs can ask it questions and get answers.
API stands for Application Programming Interface. Do not dwell on the words. Ask: who has looked at a Google Analytics report and wanted the numbers in a spreadsheet without copying? That is what the API is for. Every tool you use today has one: GA4, Meta, Shopify, Mailchimp, ChatGPT.

Intro

Request and response

Two messages. You send one, the server sends one back.

  1. You send a request: a method and an address. The method today is always GET, which means "give me".
  2. The server sends a response: a status code that says how it went, and a body with the data.
  3. The body is text. Almost always it is written in a format called JSON.
Request
GET https://www.kaggle.com/api/v1/datasets/view/rodsaldanha/arketing-campaign

Response
200 OK
{
  "title": "Marketing Campaign",
  "ownerName": "Rodolfo Saldanha",
  "downloadCount": 66157,
  "voteCount": 447
}
Read the panel out loud, top to bottom. GET plus an address goes up. A status code plus a body comes down. Everything in the next two hours is this picture with different words in it. Other methods exist (POST sends data in, DELETE removes) but we only read today.

Intro

How to read an API address

Four parts. The documentation of an API is a list of the last two.

https://www.kaggle.comBase URL. Which service you are talking to. Same for every request.
/api/v1Version. The API can change over time. You say which version you expect.
/datasets/listEndpoint. What you are asking for. The documentation lists all of them: /datasets/list, /datasets/view/…, /competitions/list
?search=marketingParameters. How you want it. Starts with ?, one name=value per parameter, joined with &.
Read it as a sentence "Kaggle, version 1, list datasets, that match marketing."
Point at each row. Students have seen parameters before in normal web addresses (utm_source=…). Same thing. Later today they change the search parameter themselves and see the answer change.

Intro

JSON: how the answer is written

Three rules and you can read any API answer.

  1. Curly braces { } hold an object: a list of "name": value pairs, separated by commas.
  2. Square brackets [ ] hold a list. Each item can be an object.
  3. Text is in double quotes. Numbers, true and false are not.

Read it out loud: "a list with two objects; the first has ref, title and downloadCount".

[
  {
    "ref": "rodsaldanha/arketing-campaign",
    "title": "Marketing Campaign",
    "downloadCount": 66157
  },
  {
    "ref": "arashnic/uplift-modeling",
    "title": "Uplift Modeling, Marketing Campaign Data",
    "downloadCount": 3239
  }
]
This is a real answer from Kaggle, shortened. The real one has 20 datasets and 40 fields each. The skill is to find the field you want and ignore the rest. JSON stands for JavaScript Object Notation, which explains why the Node script in Part 4 can read it without any extra library.

Intro

Status codes: how it went

Every response starts with a number. Learn these seven.

CodeMeansWhat to do
200OKRead the body. You got what you asked for.
302Go somewhere elseThe data is at another address. Tools follow it if you tell them to. In curl that is -L.
401Who are you?The endpoint needs a key and you sent none, or the wrong one.
403Not allowedThe key is right but your account may not see this.
404Not foundThe endpoint or the thing you named does not exist. Check the spelling of the address.
429Too many requestsSlow down. Wait a minute and try again.
500The server brokeNot your fault. Try again later.
2xx is good, 3xx is a detour, 4xx is your mistake, 5xx is their mistake. You will see 200, 302 and 401 today, on purpose. The 401 is the reason Part 2 exists.

Intro

API keys

A password for programs. It tells the API who is asking.

  • Why: the service wants to know who is asking, count the requests, and show only what your account may see.
  • Where you get it: in your account settings on the service. Never by email.
  • How it is sent: inside the request, in a part called a header. Not in the address.
  • Kaggle: one long token that starts with KGAT_. curl sends it with -H "Authorization: Bearer TOKEN".

Treat the token as a password

  • Never in a screenshot, a chat, a slide or a shared document.
  • Never in a file you upload to GitHub.
  • Leaked? Delete it on the settings page and generate a new one.
Today the token goes into the Terminal and into one file on your computer. Nowhere else.
Make the rule physical: the token goes into the Terminal and into kaggle.js on their own machine. If someone asks a chatbot for help with a command, they replace the token with the word TOKEN first. Tell them now, before they have one. Bearer is just the word HTTP uses for "the holder of this token is allowed in"; many APIs (OpenAI, Shopify, GA4) use the same header.

API or scraping?

Scraping reads a page made for people. It breaks when the page changes.

An API is made for programs. It is documented, stable and allowed.

Rule: if there is an API, use it. Scrape only when there is none.

Connect to the scraping lecture: allabolag.se had no API, so we scraped. Kaggle has one, so we do not. The list on the left is where the students will use this in their first job: pulling numbers into a sheet or a dashboard without copying.

Part 2 of 4

A Kaggle account and an API token

Register, find the API section in settings, generate a token, open a Terminal in your editor.

Part 2Step 5 of 19

Create a Kaggle account

  1. Go to kaggle.com/account/login.
  2. Click Register. Choose Register with Google or Register with your email.
  3. Fill in the form. If you used email: open the email from Kaggle and click the confirmation link.
  4. You land on kaggle.com signed in. Your profile picture is at the top right.

What is Kaggle?

A site owned by Google where people share datasets, compete in data science competitions and run notebooks.

We use it because the account is free, the API is simple and it has thousands of public datasets to practise on.

Done when you are signed in and see your profile picture at the top right of kaggle.com.
Already have an account? Sign in and wait. Kaggle may ask for a display name and a username on the first sign in. Any name is fine; the API token does not depend on it.

Part 2Step 6 of 19

Find the API section in settings

  1. Click your profile picture at the top right. Choose Settings. Or go straight to kaggle.com/settings.
  2. Scroll down until you see the heading API.
  3. Read what is there before you click anything.

What you see under API

A button Generate New Token. Below it, a smaller section Legacy API Credentials.

We use Generate New Token. The legacy one is an older username-and-key pair; the answer sheet shows how to use that too.

Done when you see the API section with the button Generate New Token.
Kaggle moves things around. If the section is missing, the account is not fully set up: check for a "verify your email" banner. Phone verification is not needed for API tokens.

Part 2Step 7 of 19

Generate the token

  1. Click Generate New Token.
  2. A dialog opens: API Token is now available. The token starts with KGAT_.
  3. Click the copy icon to the right of the token. Do not close the dialog yet.

Shown once

The dialog says: Please copy your API token now. You won't be able to view it again.

Lost it? No problem. Click Generate New Token again and you get a new one. The old one stops working.

Done when the token is on your clipboard and the dialog is still open.
The dialog also shows commands with export and mkdir. Ignore them; they are for people who install the Kaggle command-line tool. We send the token ourselves in the next part. Students who click Close too early: generate again.

Part 2Step 8 of 19

Save the token in a text file

  1. Open TextEdit (Mac) or Notepad (Windows).
  2. Paste. You get one line that starts with KGAT_ followed by 32 letters and digits.
  3. Save the file as kaggle-token.txt in your Downloads folder. Keep it open: you copy from it all day.
  4. Go back to Kaggle and click Close.
KGAT_a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4

Yours is different from everyone else's. The same token works from any computer, which is exactly why it must stay secret.

Never share the token. Not in a screenshot, not in a chat, not in a slide. If it gets out: Settings → API → delete it, then generate a new one.
Mac TextEdit may want to save as rich text: Format → Make Plain Text first. Make the point before they copy anything else: when they ask a chatbot for help later, they replace the token with the word TOKEN.

  2. Start VS Code or Cursor. File → Open Folder, choose api.
  3. Terminal → New Terminal. A window opens at the bottom. It is standing in your api folder.
  4. Type curl --version and press Enter. On Windows type curl.exe --version.
$ curl --version
curl 8.7.1 (x86_64-apple-darwin24.0) libcurl/8.7.1 …

Windows: write curl.exe

On Windows this Terminal is PowerShell, which has its own curl that works differently. curl.exe is the real one. Add .exe every time today.

Done when the Terminal answers with a line that starts with curl 7 or curl 8. The rest of the numbers do not matter.
Same setup as the scraping lecture: a folder, an editor, a terminal at the bottom. curl is a program that sends requests from the command line, preinstalled on every Mac and on Windows 10 and 11. Part 3 of 4

Requests with the key

Unlock the door, break it on purpose, then download the dataset and answer a question with it.

Part 3Step 10 of 19

Unlock the door

  1. Copy the command on the right into the Terminal. Do not press Enter yet.
  2. Replace TOKEN with your token from kaggle-token.txt. Keep the quotes. Keep the word Bearer and the space after it.
  3. Press Enter. Windows: the command starts with curl.exe.

-H means "header": curl adds one line to the request, called Authorization, with your token in it.

$ curl -H "Authorization: Bearer TOKEN" "https://www.kaggle.com/api/v1/competitions/list"
[{"ref":"arc-prize-2026-arc-agi-3","title":"ARC Prize 2026 - ARC-AGI-3", …

Same address as the locked door in step 4. This time the answer is a long list.

Done when the Terminal fills with JSON that starts with [{ instead of the 401 message.
The address is the same as in Part 1. The only difference is the header. Let that sink in: the token does not change what you ask, it changes who is asking. Common problems: the quotes left out, "Bearer" misspelled, the token pasted twice, or a line break inside the command.

Part 3Step 11 of 19

Break it on purpose

  1. Press the ↑ arrow key. The last command comes back.
  2. Change one character in the token. Press Enter.
  3. Read the answer. Then press ↑ again, fix the character, and run it once more so it works.
$ curl -H "Authorization: Bearer KGAT_a1b2…c3dX" "https://www.kaggle.com/api/v1/competitions/list"
{"code":401,"message":"Unauthenticated"}

A wrong token looks exactly like no token. The server does not tell you which. When you see 401 in real work: check the token first.

Done when you have seen the 401 message with a wrong token and the list again with the right one.
Ten seconds of work, and the most useful ten seconds of the day: they now recognise the error they will get in every future integration. The up arrow is worth showing; many have never used it.

  3. Find content-type. It tells you the body is JSON.

…

Done when you can point at the status line, one header, and where the body starts.
Headers travel in both directions: the token went up in a header, the content type comes down in one. The browser hid all of this in Part 1. curl shows it when asked.

Part 3Step 13 of 19

Download the dataset

  1. Run the command on the right, with your token.
  2. Nothing is printed. The answer went into a file. It appears in the left column of the editor.
  3. Mac: type ls -l marketing_campaign.csv. Windows: dir marketing_campaign.csv. The file is about 220 000 bytes.

-L: follow the 302 detour to where the file really is. -o: save the body under this file name.

$ curl -L -H "Authorization: Bearer TOKEN" -o marketing_campaign.csv "https://www.kaggle.com/api/v1/datasets/download/rodsaldanha/arketing-campaign/marketing_campaign.csv"

Empty file?

You forgot -L. Kaggle answers 302 and points to Google's storage. curl only goes there if you tell it to.

Done when marketing_campaign.csv shows in the left column of the editor and is around 220 KB.
The endpoint is download, then the dataset, then one file name inside it. Without the file name you get a zip with everything. The file lands in the api folder because that is where the Terminal is standing. Clicking it in the left column opens it as text, which is a nice moment: the API answered with this.

Part 3Step 14 of 19

Open the file in a spreadsheet

  1. Go to sheets.new. Choose File → Import → Upload and pick marketing_campaign.csv from your api folder.
  2. Under Separator type choose Custom and type a semicolon ;. Click Import data.
  3. Look at the columns. Row 1 is the header. The last column, AC, is called Response.

Excel: Data → From Text/CSV, delimiter Semicolon.

What the data is

2 240 customers of a food retailer. For each: birth year, education, income, how much they spent on wine, meat, fish and so on, and whether they accepted each of six marketing campaigns.

Response = 1 means the customer accepted the offer in the last campaign.

Done when you see 2 241 rows (one header plus 2 240 customers), 29 columns, and the last column AC is called Response.
The separator is a semicolon, not a comma, which is common with European data. If everything lands in column A the separator was wrong: import again. The columns U to Y are AcceptedCmp3, 4, 5, 1, 2, in that order. That odd order matters in the next step.

Part 4Step 17 of 19

Create kaggle.js

  1. File → New File. Save it as kaggle.js in the api folder.
  2. Paste the code on the right. It is also on the answer sheet, ready to copy.
  3. Replace YOUR_TOKEN with your token. Keep the quotes. Save.

Line 5 is the same Authorization header you typed after -H in curl.

const token = "YOUR_TOKEN";
const url = "https://www.kaggle.com/api/v1/datasets/download/rodsaldanha/arketing-campaign/marketing_campaign.csv";
async function main() {
  const response = await fetch(url, {
    headers: { Authorization: "Bearer " + token }
  });
  console.log("Status:", response.status);
  const text = await response.text();
  const rows = text.trim().split("\n").slice(1);
  const accepted = rows.filter(row => row.trim().split(";").at(-1) === "1").length;
  console.log("Customers:", rows.length);
  console.log("Accepted the last campaign:", accepted);
}
main();
Done when kaggle.js is saved with your token on the first line.
Walk through it in four sentences: the address, the request with the header, the response as text, and a count of rows whose last field is 1. fetch follows the 302 on its own, so no -L needed here.

  2. Three lines come back. Compare the last one with the number you got in the spreadsheet.
  3. Get an error? Read the first line of it. Customers 0 means the address is wrong. Compare it with the slide.
$ node kaggle.js

Done when the script prints Status 200 and the same count as your spreadsheet.

Summary

What you did today

A request, a token, a response, and a number nobody copied by hand.

  • An API answers with data instead of a page. The address is the question: base URL, version, endpoint, parameters.
  • The answer is a status code and a JSON body. 200 is good, 401 means the key is missing or wrong.
  • An API token travels in a header, not in the address. curl sends it with -H. A script sends the same header.
  • Open endpoints work in the browser. Locked ones need curl or code.
