Answer sheet

Every command from the lecture APIs: request, key, response, with the answer you should get. Replace TOKEN with your own Kaggle token everywhere. On Windows, write curl.exe instead of curl.

The token is a password. It does not belong in a chat, a screenshot or a file you upload. When you ask a chatbot for help with a command, replace the token with the word TOKEN first.

Part 2: account and token

  1. kaggle.com/account/login → Register → with Google or with email. Confirm the email.
  2. Profile picture → Settings, or kaggle.com/settings. Scroll to the heading API.
  3. Click Generate New Token. A dialog API Token is now available opens. Click the copy icon next to the token. It starts with KGAT_ and is shown only once.
  4. Paste it into TextEdit or Notepad. Save as kaggle-token.txt in your Downloads folder. Close the dialog.
  5. Create a folder api. Open it in VS Code or Cursor (File → Open Folder), then Terminal → New Terminal. Check: curl --version (Windows: curl.exe --version).
Lost the token? Generate New Token again. The old one stops working, which is fine.

Part 4: in code

Step 17: kaggle.js

File: kaggle.js. Replace YOUR_TOKEN, save, run node kaggle.js.

const token = "YOUR_TOKEN";
const url = "https://www.kaggle.com/api/v1/datasets/download/rodsaldanha/arketing-campaign/marketing_campaign.csv";

async function main() {
  const response = await fetch(url, {
    headers: { Authorization: "Bearer " + token }
  });
  console.log("Status:", response.status);

  const text = await response.text();
  const rows = text.trim().split("\n").slice(1);
  const accepted = rows.filter(row => row.trim().split(";").at(-1) === "1").length;

  console.log("Customers:", rows.length);
  console.log("Accepted the last campaign:", accepted);
}
main();

Two things worth knowing

Public datasets do not need the token

Kaggle lets anyone read and download public datasets without a token. That is why Part 1 works in the browser. The token matters for endpoints tied to your account, such as the competitions list, and for private datasets. Sending the token on every request is still the right habit: most APIs require it everywhere.

The legacy key: username and key

Under Legacy API Credentials on the same settings page, Create Legacy API Key downloads a file kaggle.json with a username and a key. That pair is sent with Basic authentication instead of a Bearer token:

# curl
curl -u USERNAME:KEY "https://www.kaggle.com/api/v1/competitions/list"

# Node
headers: { Authorization: "Basic " + Buffer.from(username + ":" + key).toString("base64") }

Older tutorials on the internet use this form. Both work.
