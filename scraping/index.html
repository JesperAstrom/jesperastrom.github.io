Intro

Vad är web scraping?

Ett program som läser en webbsida och plockar ut det du vill ha

I stället för att kopiera 15 868 företagsnamn för hand skriver du ett program som gör det på en minut.

  • Hämta sidan, precis som webbläsaren gör.
  • Hitta rätt bitar i HTML-koden.
  • Spara dem i en fil du kan jobba vidare med, till exempel CSV.
Definitionen i tre verb: hämta, hitta, spara. Alla verktyg vi ser idag gör ett av de tre. Siffran 15 868 är antalet träffar på "Arkitekter" på allabolag.se.

Intro

Det du redan gör varje dag

Webbläsaren är en scraper som ritar upp resultatet

Webbläsaren

  1. Skickar en förfrågan (request) till servern.
  2. Får tillbaka HTML, CSS och JavaScript.
  3. Ritar upp sidan så att du kan läsa den.

Din scraper

  1. Skickar samma förfrågan, fast från ett program.
  2. Får tillbaka samma HTML.
  3. Läser texten i koden i stället för att rita upp den.
Från tutorialen: "when you enter a website a basic GET request is sent... with request you do the same thing but you write that action yourself in Node instead of the browser handling everything". Visa gärna högerklick → Visa sidkälla (View page source) live: det är exakt det scrapern får.

Intro

Var finns datan?

Tre ställen. Kolla vilket innan du börjar koda.

1. Direkt i HTML-koden

Högerklick → Visa sidkälla. Om du hittar texten där är det enklaste fallet.

allabolag.se är så här.

2. Laddas in efteråt

Sidan är tom i källkoden och fylls på av JavaScript. Titta i DevTools → Network → Fetch/XHR, där finns ofta ett API som svarar med JSON.

Instagram, Facebook, många webbshoppar.

3. Gömd som JSON i ett script

Datan ligger i en <script>-tagg i källkoden. Klipp ut, kör igenom en JSON-validator, läs in.

Vanligt på Next.js- och React-sajter.

Tutorialen (video 4 och 15) gör exakt den här utredningen på IMDB och Instagram: först View page source, sedan Network-fliken filtrerad på XHR, sedan letar de efter JSON i källkoden. allabolag.se är byggd i Next.js och skickar faktiskt datan både som synlig HTML (fall 1) och som JSON i ett script-block (fall 3). Vi använder fall 1 idag.

Två verktygslådor

Hämta och tolka, eller styra en riktig webbläsare

fetch + cheerio

Hämta HTML med Node:s inbyggda fetch. Tolka den med cheerio, som låter dig söka i koden med CSS-selektorer.

Snabbt, enkelt, få rörliga delar. Funkar när datan finns i HTML-koden.

Det vi använder idag.

Puppeteer

Startar en osynlig Chrome som Node fjärrstyr. Kan klicka, scrolla, logga in och vänta på att JavaScript laddat klart.

Långsammare och tyngre. Behövs när sidan byggs upp först efter att den laddats.

Nästa steg när ni vill skrapa dynamiska sajter.

Intro

HTML är lådor i lådor

Tagg, attribut och innehåll

<div class="card" id="foretag-1">
  <h2>
    <a href="/foretag/tol">TOL Arkitekter AB</a>
  </h2>
  <span class="orgnr">556710-7759</span>
  <span class="phone">08-642 20 25</span>
</div>

Ett förenklat företagskort från allabolag.se. Samma exempel på de kommande sliderna.

  • Tagg säger vad det är: div, h2, a, span.
  • Attribut är extra uppgifter i starttaggen: class, id, href.
  • Klass får återanvändas: alla 25 kort har class="card". Id ska vara unikt.
  • Innehåll är texten mellan taggarna, eller fler element. Ett element inuti ett annat är ett barn.
Grundvokabulären för hela dagen. Poängen med "lådor i lådor": h2 ligger i div, a ligger i h2. Det är den strukturen selektorer navigerar i. Skriv gärna upp orden tagg, attribut, klass, id, barn på tavlan.

Intro

Bra och dåliga selektorer

Kort och unik överlever. Lång och exakt går sönder.

Skriv själv: 2–3 led

.SearchResultCard-card h2 a

Utgå från ett klassnamn eller id som bara finns på det du vill åt. Går det inte, ta närmaste förälder som är unik.

Högerklick → Copy selector: 7 led

#__next > div > main > div:nth-child(3) > div > div:nth-child(2) > h2

Snabbt när du har bråttom. Men om ett enda led ändras på sajten slutar allt fungera.

Tumregel Ju färre led i selektorn, desto större chans att scrapern fungerar nästa vecka också.
Video 10 i tutorialen. Chrome bygger en selektor med sju led; handskriven har två eller tre. "The less the better." Notera att allabolag.se har MUI-klasser som mui-1qd50v8 som genereras automatiskt och kan bytas ut vid nästa release, medan SearchResultCard-card är ett namn en människa valt. Välj det senare.

Intro

När sidan säger nej – felkoder i Consolen

Se ut som en webbläsare.

  • 403 Forbidden betyder oftast: servern ser att du inte är en webbläsare. Skicka med en User-Agent-header som en riktig Chrome har.
  • Obegripliga tecken i svaret: sidan är gzip-komprimerad. fetch löser det automatiskt, äldre bibliotek behöver gzip: true.
  • Statuskod 300 och uppåt ska fångas med try/catch så att programmet inte dör mitt i.
// allabolag.se svarar 403 utan detta
const res = await fetch(url, {
  headers: {
    "User-Agent": "Mozilla/5.0 (Macintosh; …) Chrome/128.0"
  }
});
Video 5, 6 och 13 i tutorialen. Vi testade inför lektionen: allabolag.se ger 403 utan User-Agent och 200 med. Var hittar man headers? DevTools → Network → första requesten (Document) → Request Headers. Kopiera User-Agent därifrån, eller googla "chrome user agent string".

Intro

Uppför dig

En scraper som är för snabb blir avstängd

  • Vänta mellan varje sida. En halv sekund räcker långt.
  • Fånga fel och fortsätt med nästa sida i stället för att krascha.
  • Logga i Terminalen vad som händer: vilken sida, hur många träffar.
  • Proxy byter din IP-adress. Behövs sällan som nybörjare. Använd det bara om projektet kräver det.
for (const url of urls) {
  try {
    const rows = await scrapePage(url);
    console.log(url, rows.length);
  } catch (err) {
    console.log("Fel på", url, err.message);
  }
  await sleep(500);
}
Video 12: "if you are just getting started I would highly suggest not to use proxy servers unless your project demands this." Video 13 och 17: try/catch och att vänta på att saker blir klara innan nästa varv. Väntetiden i den gamla uppgiften stod som 0,5 ms; det ska vara 500 ms.

Intro

Får man?

Öppen data är inte samma sak som fri data

  • Läs sajtens villkor och robots.txt. Många sajter förbjuder automatisk hämtning.
  • Personuppgifter omfattas av GDPR. Ett företagsnamn är inte en personuppgift, men en VD:s namn är det.
  • Belasta inte servern. Vänta mellan anrop och skrapa bara det du behöver.
  • Använd datan internt, för analys och prospektering. Publicera den inte vidare.
Idag skrapar vi ett fåtal sidor på allabolag.se i utbildningssyfte, med väntetid mellan anropen, och sparar bara företagsdata.
Ta den här slajden på allvar men snabbt. Bra övningssajt utan begränsningar när man vill leka: toscrape.com (nämns i tutorialen video 14).

Intro

Så jobbar vi idag

Du skriver prompten. Chatboten skriver koden. Du kör den.

  2. Klistra in prompten i ChatGPT, Claude eller Cursor och skicka.
  3. Chatboten svarar med kommandon och kod. Gör exakt det den säger, ett kommando i taget.
  4. Får du ett fel: klistra in hela feltexten i chatten och skriv "jag fick det här felet".
  5. Fungerar det: öppna CSV-filen och jämför med rutan Klart när på sliden.

Byt sökord och kör igen

  1. Välj en bransch du är nyfiken på, till exempel Reklambyrå, Tandläkare eller Bryggeri.
  2. Byt ut Arkitekter i alla fem adresserna i scraper.js. Har ordet å, ä eller ö: skriv det som det är, Node kodar om det.
  3. Kör node scraper.js igen och öppna foretag.csv.

Vad gör man med listan?

  • Prospektlista för säljare, med telefonnummer.
  • Adresser till en karta över konkurrenter.
  • Underlag för en marknadsanalys per stad.
Klart när du har en CSV-fil med 125 företag i din bransch. Spara den, du får användning för den senare i kursen.

Sammanfattning

Det du gjort idag

Hämta, hitta, spara. Sedan loopa.

  • En scraper skickar samma förfrågan som webbläsaren och läser HTML-koden som text.
  • CSS-selektorer pekar ut det du vill ha. Korta och unika håller längst.
  • User-Agent, väntetid och felhantering är skillnaden mellan en scraper som funkar en gång och en som funkar varje gång.
  • Chatboten skriver koden. Du styr den med tydliga prompter och ordagranna felmeddelanden.

Nästa steg

  • Dynamiska sajter: Puppeteer.
  • Inloggning och formulär: cookies och POST-anrop.
  • Gömda API:er: Network-fliken → Fetch/XHR.
  • Ladda ner bilder och filer: strömmar (streams).
